# Status audit: prompts, context, and the wiring between projects, sessions and rooms

Scope: the state of the system on 2026-09-06 after the week's changes
(rooms per project, session mirrors, the conversation index, the PARA
horizon, per-lane models). Measurements are from the live install.
Findings are ordered by what to do next; fixes made during the audit
are marked.

## 1. What a turn carries

| Lane | What the model sees | Size |
|---|---|---|
| Resident (EA channel, DM) | primer once per session, then per-turn dispatch: briefing blurb, skill blurb, thread context | primer 5.0 KB; dispatch 9 to 26 KB per turn (log `bytes=`) |
| Per-thread session, first message | CLAUDE.md core plus the topic guides for the needed modules, skill instructions, briefing extract, style rules | core 31 KB (was 67); guides 0.4 to 9 KB each; skills 205 KB in total, 27 KB for scheduling-rules alone |
| Per-thread session, follow-up | slim continuation: the user text plus reminders | under 2 KB |
| Room specialist (#ea-) | as per-thread first message, plus the project pack | pack 2 to 6 KB |
| Any of the above | CONVERSATION INDEX (other sessions) | up to 2.2 KB, on new sessions, in rooms, on cue |
| Any of the above | PROJECT INDEX (every active project) | up to 3.2 KB, with a pack, in rooms, on cue |
| Cron agents | skill file plus the briefing JSON path | morning-briefing skill 21 KB |

Findings:

- **CLAUDE.md is the largest single input and grows weekly.** It is the
  operating manual for every lane, so every new feature adds a section.
  The per-thread lane trims it by module, the resident reads it once at
  session start. It should be split: a short core (identity, safety,
  rooms, the three registries) and per-topic files pulled in by the
  skill router the way skills are. Backlog, highest value.
- **scheduling-rules.md at 27 KB is injected whole whenever scheduling
  is detected.** Half of it is examples. Backlog.
- **Two indexes can ride on one turn** (conversation plus project).
  Bounded at 5.4 KB together; acceptable, and both are cached.
- **Style rules are duplicated** into the primer and both per-thread
  prompts. Small (2 KB) and by design.

## 2. Wiring between projects, sessions and rooms

The three stores and what joins them:

| Store | Key | Holds |
|---|---|---|
| project store (SQLite) | project id | name, domain, kind, horizon, status, parent, summary, next actions, people, ledger links, journal, filed mail |
| slack-sessions.json | thread_ts | session id, title, channel, model, expired id |
| ea-channels.json | channel id | kind (project or session), project or session id, name, url, model, archived |
| Claude transcripts (ea-bot) | session id | the memory |

Findings, with the fixes made this week:

- The resident took every room when free, so a room's own session was
  reached only when the resident failed. **Fixed**: scoped rooms never
  use the resident; project rooms mint a specialist on first use.
- Project rooms had no session of their own. **Fixed**: a persistent
  session per room, pinned to the room_specialist model.
- Aged-out threads lost their session id. **Fixed**: the id rides on the
  new row; `resume this conversation` re-adopts it.
- Renames broke the badge and cost a Claude turn. **Fixed**: system
  subtypes are not messages; renames update the registry.
- No conversation knew what the others were doing. **Fixed**: the
  conversation index, from transcripts and the two registries.
- The status column could not say "standing responsibility", so
  nothing ever retired. **Fixed**: `horizon` (project, area, goal),
  a dormancy scan the weekly audit proposes from, and rooms that follow
  their project's status. Fourteen projects are now areas or goals.
- Thread rows are keyed by thread_ts alone. Slack timestamps are unique
  per channel, so two rooms can in theory mint the same key. Not seen;
  backlog: key by channel and thread_ts.
- The morning briefing's Slack read and the "already in play"
  reconciliation cover the EA channel only. Rooms are invisible to
  them. Backlog, next.
- Cron agents post to the EA channel only. A project's morning items
  could go to its room. Backlog.
- Room specialists never rotate. The resident rotates on transcript
  size; a busy room will need the same. Backlog.
- The session index is built by shelling out as ea-bot every two
  minutes at most. Cost is negligible; it reads tails only.

## 3. Models per lane

| Lane | Model | Set where |
|---|---|---|
| Resident | EA_RESIDENT_MODEL (claude-opus-5[1m]) | ~/.ea/.env |
| Per-thread default | EA_MODEL (claude-opus-5[1m]) | ~/.ea/.env |
| Room specialist | models.room_specialist (claude-fable-5-1) | ea-config.json, default in code |
| Email author (a subagent any lane calls for a body) | claude-opus-4-8 | .claude/agents/email-author.md |
| Session room (#tmp-) | the model the session was held in | channel row |
| Scheduling channel (one session per thread, CLAUDE-scheduling.md) | models.scheduler (claude-opus-5[1m]; empty means EA_MODEL) | ea-config.json |
| Morning briefing, afternoon, weekly audit | opus | run-agent.sh |
| List digest, priority, scheduling checks | sonnet | run-agent.sh |
| Pre-send audit verdict | sonnet | run-agent.sh |

Email and letter bodies are written by the `email-author` subagent on
its own model, whichever lane asks. Nothing routes a whole thread by the
kind of ask; the caller keeps the draft, the buttons and the journal.

## 4. PARA state

Horizon, live: 23 active projects, 11 active areas, 2 goals, 2 dormant
projects, 3 closed. The
dormancy scan counts a journal entry that is not bookkeeping, a filed
message or a ledger item touched as activity; every project's ledger
items were touched in August, so the first candidates appear around
2026-09-14 and the weekly audit will propose them. Areas and goals keep
their rooms; a dormant project's room is archived within ten minutes
and comes back when the project is revived.
